# v1.3-html — Bring CBA to the browser demo

**Date:** 2026-05-15
**Status:** Draft for review
**Builds on:** v1.2a (`2026-05-15-v1.2-cba-framework-design.md`, Python package)

## 1. Purpose

The Python package's `sir.cba` produces a 9-stream cost-benefit report. The browser demo (`web/index.html`) does not yet. This spec adds a simplified, mean-field CBA report to the demo so users can build intuition about cost-benefit reasoning without leaving the browser.

Two simplifications relative to the Python package:

- **No age stratification**: the demo uses mean-field arrays. Wage, working-years, and YLL become single scalars instead of 7-tuples.
- **Per-capita units**: the demo normalizes monetary streams to per-person values (e.g. "$125/person averted" rather than "$1,250,000 averted") so that scenarios at different N are directly comparable.

One advantage relative to the Python package: the demo already tracks per-day population-average θ and e, so streams 7 (behavioral loss) and 8 (precaution cost) can be wired up correctly — both are stubs in `sir.cba` v1.2a pending a v1.2b extension.

## 2. Scope

### In scope

- 9 CBA streams computed inside the existing Pyodide `simulate()`, returned alongside disease/healthcare arrays.
- Per-capita monetary units throughout (sum of streams / N).
- Daily discounting using the same `(1+r)^(-t/365)` formula as the Python package.
- New "Cost-benefit analysis" section in the sidebar with 6 always-visible Tier-A sliders and an expandable Tier-B group with 5 advanced sliders.
- New "CBA" card below the outcome plot with a stacked-bar visualization (baseline vs treatment) and a delta table.
- 3 new outcome-dropdown entries: "Cumulative monetary cost", "Cumulative YLL", "Cost per YLL averted".
- Updated summary cards: keep existing "Net welfare" (FOC-bundled), add "Total monetary cost" and "Cost per YLL averted" cards.
- Tooltips on every new control.
- `docs.html` and Detailed-tab updates noting the mean-field simplifications.

### Out of scope (v1.3 HTML)

- Age-stratified rates (use single scalars; defer to a v2 HTML when the simulation grows age structure).
- Per-stream PSA in the browser (not currently supported even in the Python package's PSA path).
- TOML import/export of CBA configurations.
- Saving runs / comparing more than two scenarios.

## 3. Architecture

The HTML demo's Pyodide simulation already runs `simulate_pair()` returning a `with_int` and `without_int` result. We add CBA computation inside `simulate()` so that each returned dict gains a `cba` sub-dict with per-stream totals and per-day arrays.

```
┌─────────────────────────────────────────────────────────┐
│ Pyodide simulate(N, T, ..., cba_params...)              │
│   - existing disease/healthcare logic                    │
│   - NEW: compute 9 CBA streams (vectorized)              │
│   - returns {S, I, R, hosp_*, deaths_*, ...,             │
│              cba: {streams, total_monetary_per_capita,   │
│                    total_yll_per_capita, ...}}           │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
                  simulate_pair()
                          │
                          ▼
           with_int.cba  +  without_int.cba
                          │
                          ▼
                  JavaScript renderResults()
                          │
                          ▼
       Outcome plot   Stacked-bar CBA card   Summary cards
```

No new Python modules. No structural changes to the Pyodide model — just an extension of the daily-loop computation to accumulate cost streams in parallel with existing outputs.

## 4. The 9 streams (HTML simplified)

| # | Stream | Formula (HTML mean-field, per-capita) | Unit |
|---|---|---|---|
| 1 | Direct medical | `(hosp_prev × $hosp + icu_prev × $icu + new_inf × $outpatient).sum() × disc / N` | $/person |
| 2 | Vaccination program | `(new_vax × ($dose + $admin + $sideeffect)).sum() × disc / N` | $/person |
| 3 | Productivity from illness | `(new_inf × wage × sick_days_effective).sum() × disc / N` | $/person |
| 4 | Productivity from death | `(daily_deaths × wage × working_years × 260).sum() × disc / N` | $/person |
| 5 | YLL | `total_deaths × PV(yll_per_death; r) × disc_at_death_day / N` | YLL/person |
| 6 | Morbidity QALY | `(new_inf × disability_weight × sick_days/365).sum() × disc / N` | QALY/person |
| 7 | Behavioral loss | `((1-θ) × m₀ × hours × VOT).sum() × disc / N` | $/person |
| 8 | Precaution cost | `(e² × VOT × hours).sum() × disc` | $/person (already population-uniform) |
| 9 | Policy costs | `Σ active interventions × $/day × disc / N` | $/person |

`sick_days_effective` blends symptomatic + hospital LOS + ICU LOS based on the mean-field rates (`hosp_rate`, `icu_rate`). `disc` is the per-day discount factor array. `PV(yll; r)` is `(1 - exp(-r·yll))/r` (PV form) or `yll` if `r==0`.

**Total monetary cost (per capita)** = streams 1 + 2 + 3 + 4 + 7 + 8 + 9.
**Total health burden** = streams 5 (YLL) and 6 (QALY) separately.

## 7. Math and discounting details

**Daily discount factor array** (length T+1):

```python
days = np.arange(T + 1)
disc = (1 + r) ** (-days / 365)
```

**Stream computation**: each per-day raw value is multiplied element-wise by `disc` before summing.

**YLL with PV form**: the lump YLL at death day t is

```
PV_yll = (1 - exp(-r * yll)) / r   if r > 0
       = yll                        if r == 0
```

So a death on day t with yll=20 at r=0.03 contributes `PV_yll(20) ≈ 15.0 years` discounted by an additional factor `disc[t] ≈ 1` (since deaths typically occur within the simulation window).

**Per-capita normalization**: all monetary streams divided by N at the end (after summing across days). Health streams (YLL, QALY) also divided by N for consistency.

## 8. Verification

Quick checks the implementation should pass (no formal unit tests since HTML is verified by the demo run):

1. With no interventions and no infections: all monetary streams = 0, total YLL = 0.
2. With baseline run: stream 1 (direct medical) > 0, stream 5 (YLL) > 0.
3. Mask mandate reduces all medical and productivity streams, may increase behavioral_loss and policy_costs.
4. Vaccination raises vaccination_program stream and may reduce medical/death streams.
5. Cost-per-YLL-averted: when treatment averts YLL, this is `Δ(monetary)/YLL_averted`. Sign and magnitude should make sense.

## 11. Success criteria

The HTML demo with CBA succeeds if:

- A user enabling mask mandate can immediately see in the CBA card whether the intervention is cost-saving (delta_monetary < 0) and read the cost-per-YLL-averted ratio.
- The stacked bar visually shows which stream dominates the cost/benefit (typically productivity loss + medical).
- Switching to a vaccination intervention shows the new vaccination_program stream becoming nonzero and the medical/death streams shrinking.
- Adjusting the discount rate from 0 to 0.05 visibly reduces the monetized health streams (especially YLL via the PV form).
- Toggling all interventions off collapses the CBA card to a single baseline column with no delta.

If any of these qualitative checks fails, the implementation is incomplete.
