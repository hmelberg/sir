# v1.1 — Healthcare outcomes, comparison wrapper, intervention uncertainty

**Date:** 2026-05-14
**Status:** Draft for review
**Builds on:** v1 spec at `2026-05-14-sir-microfoundations-abm-design.md`

## 1. Purpose

Add three missing capabilities to the Python `sir` package that the in-browser demo already has:

1. **Healthcare outcomes** — hospital admissions/occupancy, ICU admissions/occupancy, deaths, life-years lost. Age-stratified, derived post-hoc from `new_infections` per age bin.
2. **Comparison wrapper** — a high-level API that runs the same scenario with and without a given intervention set, returning a tidy delta table and matched plots.
3. **Intervention uncertainty** — the comparison wrapper accepts intervention parameters as either fixed values or probability distributions, layering an outer PSA loop over intervention strength when distributions are present.

These additions close the gap between the web demo (which surfaces all of these) and the Python package (which has a richer simulation engine but lacks the high-level reporting layer).

## 2. Scope

### In scope (v1.1)

- New `sir.healthcare` module: pure post-processing of `SimResult` into healthcare outcome series.
- Age-stratified hospital, ICU, and death rates (one value per age bin).
- New `sir.comparison` module: high-level `run_comparison()` wrapper plus simple intervention constructors (`contact_reduction`, `transmission_reduction`).
- New `sir.distributions` (or a `dist` namespace inside `sir.psa`): fluent constructors for parameter distributions for inline use.
- Intervention parameters can be either floats or `ParameterDistribution` instances; `run_comparison()` does PSA-style outer-loop sampling when any are distributions.
- New plots: healthcare curves, deaths-by-age, with-vs-without outcome comparison.
- New demo script: `scripts/run_with_vs_without.py` mirroring the web demo.

### Out of scope (v1.1; deferred to v1.2+)

- **Capacity-dependent mortality** (over-capacity hospitals → higher death rate). The healthcare module stays a pure post-processor.
- **Healthcare states inside the disease model** (S→I→H→ICU→D transitions). Hospital/ICU/death are derived from `new_infections`, not tracked as compartments.
- **Splitting `V_a` into morbidity + mortality components.** `V_a` continues to bundle everything; deaths/YLL are informational outputs, not welfare contributions. Avoiding this split prevents double-counting.
- **Combined disease-parameter + intervention-parameter PSA.** Each is supported independently; combining the two outer loops is a v1.2 concern.
- **Endogenous vaccination choice.** Vaccination remains policy-controlled (same as v1).
- **Healthcare welfare integration.** Direct costs of hospital/ICU treatment are not added to the welfare ledger in v1.1.

## 4. Healthcare outcomes module

### 4.1 Configuration

```python
@dataclass(frozen=True)
class HealthcareConfig:
    # Age-stratified rates (7 entries, matching AGE_BIN_LABELS)
    hosp_rate_by_age: tuple[float, ...]      # P(hospitalization | infected)
    icu_rate_by_age: tuple[float, ...]       # P(ICU | infected)
    death_rate_by_age: tuple[float, ...]     # IFR
    yll_per_death_by_age: tuple[float, ...]  # Avg years lost to a death

    # Delays from infection (uniform across ages)
    hosp_delay: int = 8
    icu_delay: int = 11
    death_delay: int = 18

    # Lengths of stay
    hosp_los: int = 7
    icu_los: int = 10


def default_healthcare_config() -> HealthcareConfig:
    """Plausible defaults for a moderately severe respiratory pathogen."""
    return HealthcareConfig(
        # 0-9, 10-19, 20-29, 30-39, 40-49, 50-59, 60+
        hosp_rate_by_age=(0.005, 0.005, 0.01, 0.02, 0.03, 0.06, 0.20),
        icu_rate_by_age =(0.001, 0.001, 0.002, 0.004, 0.008, 0.020, 0.060),
        death_rate_by_age=(0.0001, 0.0001, 0.0005, 0.001, 0.003, 0.01, 0.05),
        yll_per_death_by_age=(75, 65, 55, 45, 35, 25, 8),
    )
```


### 4.3 Math (per age bin a)

$$
\text{hosp\_admit}_t = \sum_a \text{hosp\_rate}_a \cdot \text{new\_inf}_{a, t - \text{hosp\_delay}}
$$

$$
\text{hosp\_prev}_t = \sum_{s=\max(0,t-\text{hosp\_los}+1)}^{t} \text{hosp\_admit}_s
$$

Same pattern for ICU. Deaths:

$$
\text{daily\_deaths}_t = \sum_a \text{death\_rate}_a \cdot \text{new\_inf}_{a, t - \text{death\_delay}}
$$

$$
\text{total\_yll} = \sum_a \text{yll}_a \cdot \text{total\_deaths}_a
$$

## 5. Required change to `SimResult`

Add one field to `sir.simulation.SimResult`:

```python
@dataclass
class SimResult:
    ...
    new_infections_by_age: np.ndarray  # (T+1, 7) — new infections per age bin per day
    ...
```

In the simulate loop, compute this via `np.bincount(world.age_bin[new_infections], minlength=7)` per day.

The existing scalar `new_infections_history` is retained for backward compatibility but is derivable as `new_infections_by_age.sum(axis=1)`.

## 6. Distributions shorthand

Add a `sir.distributions` module (or extend `sir.psa`) with a `dist` namespace for fluent inline construction:

```python
from sir.distributions import dist

dist.fixed(1.0)
dist.normal(mean=1000, sd=200)
dist.lognormal(mu=-1.95, sigma=0.15)
dist.uniform(0.5, 2.0)
dist.beta(a=8, b=8)
dist.triangular(lo=1.5, mode=2.0, hi=2.5)
dist.ci95([0.65, 0.92], family="beta")
```

Each returns a `ParameterDistribution`. This is purely syntactic sugar; the existing TOML-based PSA spec remains the way to define many parameter distributions at once.

## 7. Intervention constructors

### 7.1 Contact reduction (X·Y·Z formulation)

```python
def contact_reduction(
    people: float | ParameterDistribution,
    events_per_week: float | ParameterDistribution,
    encounters_per_event: float | ParameterDistribution,
    window: tuple[int, int],
    target: GroupType | None = None,
    spillover_cost_per_person_per_day: float = 0.0,
) -> Intervention | UncertainIntervention:
    """Contact-reduction intervention.

    Removes (X · Y · Z) / 7 person-meetings per day from the population's
    contact pool. If `target` is None, the reduction is applied as a
    uniform multiplier across all group attendances. If `target` is a
    GroupType, only groups of that type are affected.

    If any of people/events_per_week/encounters_per_event is a
    ParameterDistribution, returns an UncertainIntervention to be
    sampled by run_comparison.
    """
```

### 7.2 Transmission reduction (mask-style)

```python
def transmission_reduction(
    p_factor: float | ParameterDistribution,
    window: tuple[int, int],
    targets: set[GroupType] | None = None,
    direct_cost_per_day: float = 0.0,
) -> Intervention | UncertainIntervention:
    """Reduce per-meeting transmission by factor `p_factor` during the window.

    If `targets` is None, applies to all group types. Otherwise, only the
    specified types (e.g., {SCHOOL, WORKPLACE, COMMUNITY} for masks indoors).
    """
```

### 7.3 X·Y·Z allocation rule

When `target=None`, the X·Y·Z reduction is allocated as a **uniform multiplier on all groups**:

```
target_reduction = X · Y · Z / (7 · N)
mean_m0 = mean over groups of m_bar_g
multiplier = max(0, 1 - target_reduction / mean_m0)
For each group: group_attendance_mult *= multiplier
```

This is the simplest interpretation matching the HTML demo. When `target` is specified, the reduction is concentrated in that group type only and the multiplier is correspondingly larger.

## 8. Comparison wrapper

### 8.1 API

```python
@dataclass
class ComparisonResult:
    cfg: ScenarioConfig
    interventions_resolved: list[list[Intervention]]
    # Outer list: per-PSA-sample (length 1 if no uncertainty)
    # Inner list: the realized interventions for that sample

    baseline_results: list[MCResult]
    # One MCResult per PSA sample (or just one if no uncertainty)

    treatment_results: list[MCResult]
    # Same shape as baseline_results

    baseline_healthcare: list[list[HealthcareOutcomes]] | None
    # Outer: per-PSA-sample; inner: per-MC-run within that sample
    treatment_healthcare: list[list[HealthcareOutcomes]] | None

    intervention_samples: list[dict[str, float]] | None
    # The parameter draws for each PSA sample (if uncertainty was used)

    def outcome_deltas(self) -> pd.DataFrame:
        """Tidy DataFrame: outcome × {baseline, treatment, delta, delta_pct, ci_lo, ci_hi}.
        Outcomes include peak_I, final_attack_rate, total_deaths, total_yll,
        peak_hosp_prev, peak_icu_prev, welfare. CIs reflect uncertainty across
        PSA samples (if any) or MC runs (if not)."""

    def averted_deaths(self) -> dict[str, float]:
        """Mean and 95% CI of (baseline_deaths - treatment_deaths)."""

    def plot_outcome(self, outcome: str) -> plt.Figure:
        """With-vs-without curves for a single outcome (mean + CI band)."""


def run_comparison(
    cfg: ScenarioConfig,
    interventions: Sequence[Intervention | UncertainIntervention],
    n_runs: int,
    n_psa_samples: int = 1,
    base_seed: int = 0,
    initial_infected: int = 10,
    healthcare: HealthcareConfig | None = None,
    parallel: bool = True,
) -> ComparisonResult:
    """Run baseline (no interventions) vs treatment (given interventions),
    optionally with PSA over uncertain intervention parameters."""
```

### 8.2 Behavior

- If all interventions are concrete: ignore `n_psa_samples` (or require it to be 1); run `n_runs` baseline + `n_runs` treatment.
- If any intervention is uncertain: draw `n_psa_samples` joint samples of all uncertain parameters; for each draw, run `n_runs` baseline + `n_runs` treatment. **The same seeds are used for baseline and treatment in each PSA sample**, so the comparison is paired and variance reduction kicks in.
- If `healthcare` is provided, compute healthcare outcomes for every simulation run.

### 8.3 Common-seed paired design

For each (PSA sample, MC index) pair, baseline and treatment use the same RNG seed. This makes the comparison a paired test (less variance) and ensures the only systematic difference is the intervention.

## 11. Verification strategy

| Test | Expected outcome |
|---|---|
| Zero infections | All healthcare outcomes zero |
| Zero rates | Hospital/ICU/deaths all zero |
| Single infection at t=0 | Hospitalization exactly one age-rate × 1 person at day hosp_delay |
| Conservation | total_deaths ≤ total cumulative R |
| YLL math | total_yll = Σ yll_a × total_deaths_a |
| Comparison: no interventions | baseline == treatment, all deltas zero |
| Comparison: zero-effect intervention | deltas ≈ 0 within MC variance |
| Comparison: hard lockdown | total_deaths_delta < 0 with high confidence |
| Distribution: fixed | Identical to passing a float |
| Distribution: normal(μ, 0) | Identical to passing μ |
| PSA reproducibility | Same seed → same sample → same outcome |

## 12. Confirmed design decisions (from discussion)

1. **Age-stratified healthcare rates** — use the ABM's per-agent age data; uniform rates would throw away v1's main advantage.
2. **`V_a` stays bundled** — deaths and YLL are informational outputs, not welfare contributions in v1.1.
3. **X·Y·Z default allocation is uniform** across groups; targeted via `target=GroupType.X` parameter.
4. **Healthcare is post-processing**, not in-loop. No capacity-dependent mortality.
5. **Paired common-seed design** for baseline vs treatment in each PSA sample.
6. **PSA only kicks in if a distribution is passed** — `n_psa_samples` is otherwise ignored. Zero-cost for the simple path.
7. **`dist` namespace** for inline distribution construction; TOML PSA spec still works for scenario-level parameter uncertainty.

## 13. Open questions

These were raised in discussion but the resolution can be tentative; revisit during implementation if needed.

1. **Spillover-cost defaults for `contact_reduction`** — should there be a non-zero default (analogous to school-closure learning loss), or zero by default and the user adds it? **Recommendation: zero by default.** User can pass `spillover_cost_per_person_per_day=` explicitly.

2. **`UncertainIntervention` class structure** — is it a distinct dataclass, or just an `Intervention` with `ParameterDistribution`-typed fields? **Recommendation: distinct lightweight dataclass that captures the symbolic spec and resolves to a concrete `Intervention` at sample time.**

3. **Whether to expose `new_infections_by_age` in MCResult** — currently in SimResult only. Probably yes for downstream PSA convenience; minor extension.

## 14. Success criteria

The wrapper succeeds if a user can answer the following questions with single-call API:

- "If I close schools for 60 days starting day 30, how many deaths do I avert? With 95% CI?"
- "If the per-event encounter count Z for school closure is uncertain in [5, 15], what's the range of deaths averted?"
- "Compared to no interventions, how does combined mask + school closure affect peak hospital occupancy?"
- "For my chosen intervention mix, what is the expected delta in total life-years lost?"

Each of these is one `run_comparison()` call producing a tidy delta table.
