sir — Microfounded epidemic ABM

Full documentation for the Python package and modeling framework.

This page documents the Python package sir: a discrete-time, agent-based SIR model with rational behavioral response, structured contacts, interventions, healthcare outcomes, and probabilistic sensitivity analysis. For a non-technical overview, the interactive demo is the right place to start. For the mathematical specification in detail, see the Detailed tab on the demo. This page covers using the Python package.

1. Overview

The classical SIR model lumps everything about disease spread into a single rate parameter $\beta$. This package decomposes $\beta$ into two interpretable components:

$$\beta = m \cdot p$$

$m$ = average meetings per person per day, $p$ = probability of transmission given a meeting between susceptible and infected.

Interventions act directly on $m$ (contact reduction: closures, gathering limits) and $p$ (precaution: masks, ventilation). Agents adjust both endogenously by solving a per-period optimization that balances the utility of social contact against the expected cost of infection. The package wraps this into a high-level API so that policy comparisons return tidy tables with confidence intervals.

The package has three layers:

LayerModulesWhat it does
Core simulationworld, simulation, transmission, disease, foc, welfare, interventionsBuild a world, step the ABM forward, accumulate per-day welfare
Reportingmonte_carlo, healthcare, plotsStochastic ensembles, derived healthcare outcomes, standard plots
Analysiscomparison, psa, distributionsHigh-level wrappers: with-vs-without comparison and PSA

Most users will only interact with the analysis layer. The core layer is exposed for customization.

  • numpy ≥ 1.26
  • scipy ≥ 1.11 (for the FOC root-find via brentq)
  • pandas ≥ 2.1 (for the comparison delta table)
  • matplotlib ≥ 3.8 (for plot helpers; not required if you only use the analysis layer)

3. Quick start

The simplest meaningful use: compare a baseline epidemic against an intervention-laden scenario and print the delta table.

from sir.comparison import run_comparison, transmission_reduction
from sir.config import default_config
from sir.constants import GroupType
from sir.healthcare import default_healthcare_config

cfg = default_config()
hc = default_healthcare_config()

interventions = [
    transmission_reduction(
        p_factor=0.5,
        window=(20, 120),
        targets={GroupType.SCHOOL, GroupType.WORKPLACE, GroupType.COMMUNITY},
    ),
]

result = run_comparison(
    cfg, interventions=interventions, n_runs=10,
    initial_infected=10, healthcare=hc,
)

print(result.outcome_deltas().round(2))

This runs 10 baseline simulations and 10 treatment simulations with paired seeds (same RNG state for each run pair, so the only systematic difference is the intervention), then prints:

                      baseline    treatment      delta  delta_pct
outcome

final_attack_rate        0.27         0.06       -0.21    -78.2
total_deaths            18.86         4.12      -14.74    -78.1
total_yll              270.92        49.30     -221.62    -81.8
peak_hosp_prev           6.04         3.10       -2.94    -48.7
peak_icu_prev            2.29         1.21       -1.08    -47.1
welfare           10968402.5   11052103.6    83701.1      0.8

Welfare can actually improve under intervention here because averted infections outweigh the small attendance-utility loss. This kind of trade-off is what the model is designed to surface.

4. Core concepts

Agents and groups

The world contains N agents (default 10,000) with attributes including age (binned into 7 groups), disease state, and group memberships. Agents belong to multiple groups simultaneously: a household, possibly a school or workplace, possibly recurring leisure venues, and the community. Each group has a type, a size, an attendance multiplier, and a transmission multiplier.

Disease state

Four states: S (susceptible), I (infected), R (recovered), V (vaccinated; still at risk but with reduced transmission). Transitions:

  • $S \to I$ via per-day per-group hazard
  • $V \to I$ at rate (1 − v_eff) times the susceptible hazard
  • $I \to R$ with daily probability $\gamma$
  • $S \to V$ via vaccination intervention

Behavioral choice

Each day, each agent chooses an attendance multiplier $\theta \in [0,1]$ on voluntary groups (kin, leisure, community) and a precaution effort $e \in [0,1]$ on all interactions. They maximize per-period flow utility:

$$U(\theta, e \mid I/N) = \sum_g \alpha_g \log(1 + m_g(\theta)) - \tfrac{1}{2}\kappa e^2 - V_a \cdot \pi(\theta, e; I/N)$$

where $\alpha_g$ is the utility weight per group, $\kappa$ is the cost of precaution, $V_a$ is the age-specific cost of getting infected, and $\pi$ is the per-period infection probability. Agents react to true prevalence (rational expectations) and treat their own action as not affecting aggregate prevalence (atomism). The gap between private and social optimum is the externality that justifies policy.

Welfare

Welfare is the sum of per-agent flow utilities over time, decomposed into 6 components: attendance utility (+), precaution cost (−), infection cost (−), vaccination cost (−), direct policy cost (−), spillover policy cost (−). The welfare_components field of MCResult exposes each.

5. API reference

Configuration

from sir.config import default_config, ScenarioConfig

default_config() returns a ScenarioConfig with v0.2 defaults: $N=10\,000$, $T=365$, $\gamma=1/7$, $\kappa=1.0$, $v_{\text{eff}}=0.8$, with 7-tuple $V_a$ scaling from 0.5 (kids) to 30 (elderly). To override:

cfg = default_config()
cfg = type(cfg)(**{**cfg.__dict__, "N": 5000, "T": 180})

ScenarioConfig is a frozen dataclass, so this idiom is the way to spawn modified copies.

Simulation

from sir.simulation import simulate
result = simulate(
    cfg, interventions=[], rng=np.random.default_rng(0),
    initial_infected=10,
)

Returns a SimResult with histories of S, I, R, V (each length T+1), new_infections_history (scalar per day), new_infections_by_age (T+1 × 7), a WelfareLedger, and the final World.

Monte Carlo

from sir.monte_carlo import run_mc
result = run_mc(
    cfg, interventions=[interventions...], n_runs=20,
    base_seed=0, parallel=True,
    healthcare=hc,  # optional; computes healthcare outcomes per run
)

Returns an MCResult: histories stacked into (n_runs, T+1) arrays, plus welfare_totals and (if healthcare= is provided) a healthcare_outcomes list of HealthcareOutcomes per run.

parallel=True uses ProcessPoolExecutor across all cores. As of v0.2, every intervention constructor produces pickle-safe objects so parallel works even with interventions enabled.

6. Interventions

Interventions are time-windowed objects that modify group properties or move agents between states. There are two families of constructors:

Setting-specific (in sir.interventions)

ConstructorEffect
close_schools(start_day, end_day)Deactivates all school groups; emits a learning-loss spillover cost
wfh_mandate(start_day, end_day, attendance_factor)Scales workplace attendance by attendance_factor (e.g. 0.3 = 30%)
mask_mandate(start_day, end_day, target_types, p_factor)Scales transmission probability by p_factor in specified group types
gathering_limit(start_day, end_day, max_size)Scales attendance to 0.1× in any group above max_size
event_ban(start_day, end_day)Deactivates all one-off events
vaccinate_eldest_first(start_day, end_day, doses_per_day)Each day moves doses_per_day oldest susceptibles to V

Generic constructors (in sir.comparison)

transmission_reduction(p_factor, window, targets=None, direct_cost_per_day=0)

Mask-style intervention that scales group_p_mult by p_factor in the given group types (default: all groups) during the window.

contact_reduction(people, events_per_week, encounters_per_event, window, target=None, spillover_cost_per_person_per_day=0)

X·Y·Z formulation: removes (X · Y · Z) / 7 person-meetings per day. If target is given, the reduction concentrates in that group type; otherwise spread uniformly across all groups.

vaccination(doses_per_day, window, uptake_rate=1.0)

Eldest-first vaccination rollout. Effective daily doses = doses_per_day × uptake_rate, so the uptake_rate parameter captures refusal at the population level (set 0.8 if you expect 20% of those offered to decline). Vaccinated agents move to the V state and remain at risk, but their per-meeting transmission probability is scaled by (1 − cfg.v_eff) — efficacy is a scenario parameter (default 0.8) rather than an intervention parameter, since it characterizes the vaccine itself.

from sir.comparison import vaccination

inter = vaccination(doses_per_day=50, window=(20, 200), uptake_rate=0.8)
# Returns an Intervention; pickle-safe; works with parallel=True

Both doses_per_day and uptake_rate accept ParameterDistribution values, in which case the function returns an UncertainIntervention ready for PSA. See §9 for an example.

Composing interventions

Pass a list to run_mc or run_comparison. They are applied in order each day; effects on group properties compose (e.g. mask + WFH multiplies the relevant scalings).

Pickle-safety

All constructors return Intervention instances whose callables are module-level or functools.partial wrappers. They pickle cleanly and work with parallel=True.

7. Healthcare outcomes

Healthcare outcomes (hospital, ICU, deaths, YLL) are post-processing — they are computed from the simulation's new_infections_by_age trajectory, not as additional disease states. This keeps the model fast and means you can adjust healthcare parameters without re-running simulations.

from sir.healthcare import HealthcareConfig, default_healthcare_config, compute_healthcare_outcomes
hc_cfg = default_healthcare_config()
# Returns a HealthcareConfig with v0.2 defaults:
#   hosp_rate_by_age: (.005, .005, .01, .02, .03, .06, .20)
#   icu_rate_by_age:  (.001, .001, .002, .004, .008, .020, .060)
#   death_rate_by_age: (.0001, .0001, .0005, .001, .003, .01, .05)
#   yll_per_death_by_age: (75, 65, 55, 45, 35, 25, 8)
#   hosp_delay=8, icu_delay=11, death_delay=18
#   hosp_los=7, icu_los=10

Each 7-tuple corresponds to the age bins 0-9, 10-19, 20-29, 30-39, 40-49, 50-59, 60+. Compute outcomes from a single simulation:

from sir.simulation import simulate
import numpy as np
result = simulate(cfg, interventions=[], rng=np.random.default_rng(0))
hc_out = compute_healthcare_outcomes(result, hc_cfg)
print(hc_out.total_deaths, hc_out.total_yll)

Or wire it into Monte Carlo to compute per-run outcomes automatically:

mc_result = run_mc(cfg, interventions=[], n_runs=20, healthcare=hc_cfg)
deaths_per_run = [hc.total_deaths for hc in mc_result.healthcare_outcomes]

The math

For age bin $a$:

  • Daily admissions: $\text{hosp\_admit}_t = \sum_a \text{hosp\_rate}_a \cdot \text{new\_inf}_{a,\,t-\text{hosp\_delay}}$
  • Prevalence: rolling sum of admissions over the last $\text{hosp\_los}$ days
  • Deaths: same pattern with $\text{death\_rate}$ and $\text{death\_delay}$
  • YLL: $\text{total\_yll} = \sum_a \text{total\_deaths}_a \cdot \text{yll\_per\_death}_a$

8. Comparison wrapper

The high-level API:

from sir.comparison import run_comparison result = run_comparison( cfg, interventions, n_runs, n_psa_samples=1, base_seed=0, initial_infected=10, healthcare=None, parallel=True, )

Runs n_runs simulations of baseline (no interventions) and n_runs simulations of treatment (your interventions) with paired seeds — so the same RNG state seeds each baseline/treatment pair, and the only systematic difference is the intervention.

ComparisonResult

The returned object holds the underlying MCResults plus optional healthcare outcomes. The most useful methods:

df = result.outcome_deltas()
# pd.DataFrame indexed by outcome:
#   peak_I, final_attack_rate, welfare
#   total_deaths, total_yll, peak_hosp_prev, peak_icu_prev  (if healthcare=...)
# Columns: baseline, treatment, delta, delta_pct, ci_lo, ci_hi

Paired-seed design

For each (PSA sample, MC index) pair, baseline and treatment share the same RNG seed. This means each delta is a paired difference, which reduces variance compared to independent seeds. CIs reported by outcome_deltas() are 2.5/97.5 percentiles of the delta distribution across runs.

9. Uncertainty (PSA)

Any intervention parameter can be a probability distribution rather than a fixed value. When run_comparison detects this, it switches on probabilistic sensitivity analysis: outer-loop samples of intervention parameters, inner-loop MC over seeds.

from sir.distributions import dist # Fluent constructors for inline use: # dist.normal(mean=, sd=) # dist.lognormal(mu=, sigma=) # dist.uniform(lo, hi) # dist.beta(a=, b=) # dist.triangular(lo=, mode=, hi=) # dist.ci95(lo, hi, family="normal") # CI shorthand # dist.fixed(value)
from sir.comparison import transmission_reduction, run_comparison
from sir.distributions import dist

interventions = [
    transmission_reduction(
        p_factor=dist.beta(a=8, b=8),    # mean 0.5, sd ~0.12
        window=(20, 120),
    ),
]

result = run_comparison(
    cfg, interventions=interventions,
    n_runs=10, n_psa_samples=30,
    initial_infected=10, healthcare=hc_cfg,
)
print(result.outcome_deltas())
print(result.intervention_samples)   # the 30 parameter draws

The PSA loop draws all uncertain parameters jointly per outer iteration, then runs n_runs × 2 simulations (baseline + treatment) for that draw. With n_psa_samples=30 and n_runs=10, that's 600 total simulations.

Vaccination with uncertain uptake

Uptake is often the most uncertain part of a vaccination rollout. The same pattern works:

from sir.comparison import vaccination

interventions = [
    vaccination(
        doses_per_day=50,
        window=(20, 200),
        uptake_rate=dist.beta(a=8, b=2),   # mean 0.8, sd ~0.12
    ),
]
result = run_comparison(cfg, interventions, n_runs=10, n_psa_samples=30, healthcare=hc_cfg)
print(result.outcome_deltas())

You can also make doses_per_day a distribution (e.g. dist.uniform(30, 80)) to reflect uncertainty in rollout capacity, or mix multiple uncertain interventions in the same call.

PSA over disease/behavioral parameters

For uncertainty on disease parameters (not intervention strength), use the older PSA workflow with a TOML spec via sir.psa.load_psa_spec and sir.psa.run_psa. The comparison wrapper handles intervention parameters; the older PSA covers everything else.

10. Welfare accounting

Welfare is the signed sum of six components:

ComponentSignSource
attendance_utility+$\sum_g \alpha_g \log(1 + m_g)$ summed over agents and time
precaution_cost−$\tfrac{1}{2}\kappa e^2$ per agent per day
infection_cost−$V_a$ per new infection
vaccination_cost−$c_{\text{vax}}$ per newly vaccinated agent
direct_policy_cost−Admin/enforcement, set by each intervention
spillover_policy_cost−e.g. learning loss from school closures

The WelfareLedger on each SimResult has a totals dict and a by_day list with per-day breakdowns. Access:

result.welfare.total_welfare()                # signed sum
result.welfare.totals["infection_cost"]       # individual component
result.welfare.by_day[10]                     # day-10 breakdown

The MCResult.welfare_components dict gives per-run arrays of each component.

11. Mathematical notes

This section sketches the math; the interactive demo's Detailed tab has the canonical reference.

Transmission

Per-susceptible per-day infection probability under the Reed–Frost form:

$$\pi_t = 1 - (1 - p)^{m \cdot I_t / N}$$

derived from: $m$ daily meetings, each meeting partner infected with probability $I_t/N$, each such meeting transmitting with probability $p$. For small $p \cdot m \cdot I/N$ this reduces to the standard mass-action $\beta I/N$ with $\beta = mp$. The basic reproduction number:

$$R_0 = \frac{m \cdot p}{\gamma}$$

FOC

The behavioral choice problem has closed-form first-order conditions. Define $A = \sum_{\text{vol}} p_g m_g (I_g/N_g)$ (exposure intensity from voluntary groups) and $B = \sum_{\text{inst}} p_g m_g (I_g/N_g)$ (institutional groups, not choosable). Then:

$$e^* = \min\!\left(1,\; \frac{V_a (\theta A + B)}{\kappa}\right), \qquad \frac{\alpha_g m_g}{1 + \theta m_g} = V_a (1 - e^*) A$$

The second equation is solved in 1-D for $\theta$ via scipy.optimize.brentq with corner-solution handling.

Bipartite contact network

Agents are members of multiple groups. Each group $g$ has a per-meeting transmission probability $p_g$, baseline attendance $\bar m_g$, and a current attendance multiplier (set by interventions and behavior). The daily hazard for a susceptible $i$ in groups $\mathcal{G}(i)$:

$$\text{hazard}_{i,t} = \sum_{g \in \mathcal{G}(i)} a_{i,g,t} \cdot p_g \cdot (1 - e_i) \cdot \frac{I_{g,t}}{N_g}$$

Infection probability: $1 - \exp(-\text{hazard}_{i,t})$.

12. Calibration

The default parameters target an $R_0 \approx 2.5$ respiratory pathogen, but they're illustrative — not derived from a specific real-world disease. If you want to model a particular pathogen, you'll typically want to adjust:

ParameterWhereNotes
$\gamma$ScenarioConfig.gamma$1/\gamma$ = mean infectious period
$p_g$ per group typeScenarioConfig.group_p_baselineSum × $\bar m$ / $\gamma$ should give your target $R_0$
$V_a$ per age binScenarioConfig.V_aDrives behavioral response; higher = more cautious
$v_{\text{eff}}$ vaccine efficacyScenarioConfig.v_effPer-vaccinee transmission reduction (default 0.8). Only matters if a vaccination intervention is active.
Healthcare ratesHealthcareConfig.*_by_ageIndependent of disease dynamics; tune freely
Identifiability caveat. $m$ and $p$ are not separately identifiable from epidemic case data alone — only the product matters. To pin them down you need outside information (contact diaries for $m$; lab transmission studies for $p$). The package's separation is for policy interpretation, not because the data can distinguish them.

The behavioral parameters

The FOC needs $\alpha_g$ (utility weights), $\kappa$ (precaution cost), $V_a$ (infection cost). These are taste parameters that should be calibrated against observed behavioral data: how much did contacts actually drop during past outbreaks, how much did mask compliance rise, etc.

The default $\alpha_g$ values are tuned so that with no disease, every agent chooses $\theta=1$ (their baseline attendance). Under typical $V_a$ values, behavioral response is modest in absolute terms but significant relative to the no-behavior counterfactual. To see this, run the simulation with behavioral=False as a baseline.

13. Scope and limitations

  • Myopic optimization. Agents react to current prevalence, not anticipated future paths. Real populations often pre-empt waves.
  • Rational expectations. Agents observe true prevalence, not lagged or media-distorted signals. Real populations over-react early and under-react late.
  • Generic respiratory pathogen. Defaults are not calibrated to a specific real disease.
  • Healthcare is post-processing. No capacity-dependent mortality, no hospital→ICU transition dynamics.
  • Exogenous vaccination. Vaccination is policy-controlled; agents do not choose to vaccinate.
  • One welfare measure. The 6-component decomposition reflects modeling choices; other formulations (e.g. equity-weighted, or splitting morbidity from mortality) are not implemented.
  • Atomism. Agents take aggregate prevalence as exogenous. This is what generates the externality but means no individual game theory between agents.

These are all intentional simplifications for v0.2. For policy use, each would need to be considered carefully.
